# 《云海邮差》v0.50 失败复盘与系统平衡验收

> 验收日期：2026-07-27  
> 版本：0.50.0  
> 范围：失败归因、构筑/路线总结、快速重开、分维度胜率、证据约束的首轮平衡  
> 原则：真人记录决定是否调数，自动模拟只做确定性回归

## 验收目标

玩家失事后无需离开当前页，即可理解“什么造成致命伤害、哪项实际风险最突出、当前构筑短在哪里”，并选择一个明确的新策略，以同种子验证、同合同换种子或调整合同后立即重新出发。

## 失败复盘

| 验收项 | 结果 |
|---|---|
| 致命原因 | 显示伤害机制、敌机、致死回合、攻击原值、护盾吸收、击中前机体与实际机体损失 |
| 关键失误 | 从过热、手牌、航道、追踪、灾变打断/规避/命中、行动效率与合同触发中选择最强风险信号 |
| 构筑短板 | 检查伤害/支援密度、牌组膨胀、强化覆盖、模块和永久改装；无可靠快照时明确降级 |
| 新策略 | 固定只给一条可执行策略，例如保留位移、压低热量、补足支援、删基础牌或集中强化 |
| 构筑总结 | 显示牌组核心副本、攻击/支援、强化与A/B分支、模块、机体改装 |
| 合同总结 | 显示整局合同被动触发次数与合同风险报酬邮票 |
| 路线收益 | 比较离港与终局快照，显示邮票、机体、货物、加牌、删牌、强化与模块净变化 |
| 战斗汇总 | 显示整局回合、出牌、受伤、过热、灾变处理与追踪命中 |

关键失误属于基于记录的风险判断，不宣称是不可证伪的唯一因果。终局快照会写入实际0机体和最终货物，而不是战斗入口状态。

## 快速重开与终局一致性

| 路径 | 合同 | 种子 | 用途 |
|---|---|---|---|
| 同种子复飞 | 保留 | 保留 | 只改变一项策略并验证结果 |
| 同合同·新种子 | 保留 | 重建 | 保留构筑目标，重排编队、奖励和商店 |
| 调整合同 | 重选 | 标准配送重建；挑战保持固定 | 直接改变合同机制与开局牌 |

- 三项固定种子挑战禁用“新种子”按钮，文案明确说明挑战种子锁定。
- 失败归档成功后删除主存档、备份和临时存档，标题页不能继续一个已结算的失败检查点。
- 档案写盘失败时保留本局存档并自动幂等重试；只有档案成功落盘后才清理运行存档。
- 每次出发生成独立AttemptId；档案保存最近128个已结算标识，重复提交不会重复累计失事或胜率。
- 同种子复飞会生成新的AttemptId，因此是可合法独立结算的新尝试。

## 胜率统计

邮政档案“胜率分析”页只统计有明确终局的本地尝试：

- 合同：按五类合同分别统计送达/已结算。
- 构筑：按火力、机动、防护、调度、混合主轴统计。
- 路线：按高压、补给、静默、混合航线统计。
- Boss：只统计实际到达Boss的战斗，不把途中失事计为Boss失败。

自动回归另外输出合同、9套构筑、2条路线与2名Boss的分项报告，并为Boss同时给出整局通关率、到达率和到达后的Boss战胜率。

## 真人证据与数值调整

本机旧档可核实的完整真人记录只有2局，均为零度血清送达；`RunsStarted=21`受编辑器界面预览污染，不能作为21局真人样本。旧档版本早于v0.49构筑快照，无法还原商店支出和路线决策。

因此本轮只做两项同时受到真人记录与旧回归支持的小幅卡牌调整：

| 项目 | v0.49 | v0.50 | 理由 |
|---|---:|---:|---|
| 霜脉长枪低热追加 | 6；升级8 | 5；升级7 | 一费低热峰值高于需要消耗锁定/动量的同级终结牌；零度循环旧回归2/2且满机体 |
| 余量点射基础伤害 | 7；升级10 | 8；升级11 | 余量调度旧回归1/2且平均62.5回合，但货物完整，表现为收尾慢而非机制失败 |

敌人、Boss、合同倍率、战斗奖励、商店价格、删牌/改写费用、路线收益和维修数值均不调整。现有真人样本不足以支持这些跨系统修改，自动模拟结果也不作为改动许可。
