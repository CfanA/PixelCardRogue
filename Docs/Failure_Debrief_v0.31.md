# 《云海邮差》v0.31 失败复盘与快速再试

## 目标

失败必须回答三个问题：

1. 我为什么失败？
2. 下一次可以做什么不同的选择？
3. 我现在能否迅速开始下一局？

v0.31 不改变任何伤害、机体、敌人、卡牌、奖励或经济数值，只改善规则解释、复盘与重试流程。

## 结构化致命来源

`BattleState` 会在规则结算时记录致命来源、来源名称和最后机体损失，不依赖界面文本或动画反推。

来源分为：

- 同航道直接攻击；
- 噬邮兽航道封锁；
- 风暴气囊全航道风暴；
- 连续换道导致的航迹追踪；
- 灾变无人机蓄力攻击；
- 首领核心正面冲击；
- 首领第二阶段邻道溅射；
- 玩家主动出牌触发的引擎过热。

每场遭遇开始时会清空上一场的致命来源，避免跨战斗污染。

## 失败复盘页

失败页显示：

- 致命机制；
- 造成致命伤害的敌机或系统；
- 最后损失的机体值；
- 针对该机制的下一次可执行动作；
- 本次失事已经写入邮政档案；
- 当前单局种子；
- 灾变打断、规避、命中或当前编队摘要。

建议使用操作语言，例如“离开标记航道”“停留一回合降低暴露”“保留冷却牌”，避免只有“注意走位”一类无法执行的泛化提示。

## 三种失败后选择

- **同合同再试**：保留当前合同，生成新单局种子并直接返回航线起点。
- **更换合同**：返回合同选择页。
- **返回标题**：不覆盖当前自动存档；玩家仍可通过“继续配送”从本场入口重新挑战相同种子。

快速再试会正常登记一次新出发。失败尝试已经单独记录，因此档案能够展示同一玩家从失败到送达的过程。

## 档案 v2

失败历史现在额外保存致命来源和敌机名称。

v1 档案迁移到 v2 时：

- 保留全部统计、发现和最近记录；
- 旧失败记录因没有可靠来源信息，显示为原遭遇类型；
- 新失败记录显示具体致命机制；
- 不伪造或猜测旧记录的死亡原因。

## 回归验证

构建前规则校验覆盖：

- 出牌导致的致命过热；
- 噬邮兽造成的致命航道封锁；
- 灾变无人机造成的致命蓄力攻击；
- 致命来源和敌机名称在战斗开始时重置；
- v1 邮政档案迁移到 v2；
- 原有战斗数值和构筑模拟基线不变。

## 后续试玩观察

外部试玩应记录：

- 玩家是否会阅读致命原因；
- 玩家能否复述下一次要改变的操作；
- 失败后选择同合同再试、相同种子重试或更换合同的比例；
- 同一机制连续造成失败时，建议是否足够清晰；
- 档案中的失败原因是否帮助玩家形成长期目标。
