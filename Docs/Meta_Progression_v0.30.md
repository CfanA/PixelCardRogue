# 《云海邮差》v0.30 局外留存与邮政档案

## 设计目标

v0.30 让每次配送都留下可见痕迹，为玩家提供回顾、收集和长期身份感，同时不引入永久伤害、机体、经济或抽牌优势。

这保证了新玩家和长期玩家仍在相同战斗规则下做决策；留存来自“我经历过什么、还没见过什么、下一次想完成什么”，而不是重复刷取数值。

## 邮政档案

标题页新增“邮政档案”，最终送达页也可直接进入。档案包含：

- 邮差等级：只由已完成配送数量决定，是纯荣誉称号。
- 履历统计：出发、送达、失事、战斗胜利、最佳货物、累计回合和累计出牌。
- 发现图鉴：四类合同、全部卡牌、模块和敌机。
- 荣誉签章：首航、发现首领、完好送达、失事后成功送达、登记全部合同。
- 最近记录：最多保留八次送达或遭遇失事摘要，包含合同、航点、遭遇、种子、回合和牌组规模。

“失事”记录代表一次失败的战斗尝试。玩家从自动存档继续并再次挑战时，会产生新的尝试记录；这能真实表现同一航点上的学习过程。

## 持久化与恢复

邮政档案与当前单局存档完全分离：

- `run.json`：当前可继续配送；完成配送后删除。
- `archive.json`：长期职业档案；完成配送后继续保留。
- `archive_backup.json`：上一个完整档案。
- `archive.tmp`：写入中的临时文件。

档案使用临时文件写入和安全替换。主档案损坏时会读取上一份备份；主档案和备份均不可读时使用新的空档案，但不会主动删除损坏文件。

Windows 默认目录：

`%USERPROFILE%\AppData\LocalLow\Portfolio Prototype\Sky Courier Prototype`

档案只保存在本机，不上传，不包含用户名、设备标识或其他个人信息。

## 数据采集时机

- 签署合同：登记一次出发、合同和初始牌组。
- 进入战斗：登记本场敌机、当前牌组和模块。
- 获得卡牌、购买卡牌或安装模块：更新发现图鉴。
- 战斗胜利：增加战斗胜利次数。
- 战斗失败：写入一次失事尝试。
- 首领战完成：写入完整送达记录与最佳成绩。

打开档案、返回标题或退出游戏不会修改统计。

## 构建前验证

`Tools > Sky Courier > Validate Core Rules` 额外验证：

- 重复卡牌与敌机发现会去重；
- 出发、胜利和送达统计正确聚合；
- 完整配送记录保留种子和结果；
- 首次送达会获得对应邮差等级；
- 主档案损坏后可恢复上一份备份。

## 后续边界

v0.30 暂不锁定现有合同、卡牌或模块，也不发放永久属性。下一步应先通过外部试玩观察玩家是否会主动查看档案、是否理解未发现项目，以及最近失败记录是否能推动再次尝试，再决定加入新的玩法型解锁。
