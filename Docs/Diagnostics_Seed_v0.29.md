# 《云海邮差》v0.29 种子与本地诊断

## 目标

当玩家报告异常时，开发者应能确认游戏版本、单局身份、所在航点、遭遇入口和基础战损，并用相同种子重新生成该场战斗的编队、初始洗牌与后续随机选择。

本轮没有修改卡牌、敌人、合同、奖励或经济数值。

## 可复现种子

- 每次开始新配送时生成一个非零 `RunSeed`。
- 遭遇种子由 `RunSeed + 航点 ID + 遭遇类型` 确定性派生。
- `BattleState` 在每次进入遭遇时重置自己的随机源；编队变体、洗牌和战斗内随机目标均使用这个随机源。
- 存档记录单局种子和当前遭遇种子。战斗中退出后选择“继续配送”，会从完全相同的遭遇入口重开。
- v1 存档会迁移到历史种子 `70422`，继续游戏不会因为缺失字段而失效。
- 单局种子以八位十六进制显示在航线状态、暂停菜单和最终结算页。

当前可复现边界是“遭遇入口”，并非逐行动回放。玩家在战斗中退出后仍会失去尚未保存的出牌进度，这与现有存档承诺一致。

## 本地诊断

Windows 默认目录：

`%USERPROFILE%\AppData\LocalLow\Portfolio Prototype\Sky Courier Prototype\Diagnostics`

文件：

- `latest-run.jsonl`：本次启动的关键事件。
- `previous-run.jsonl`：上一次启动的关键事件。
- `last-error.json`：最后一次 Unity Error、Exception 或 Assert 及堆栈。

关键事件包含 UTC 时间、游戏版本、单局种子、界面、航点、遭遇、合同、机体、货物和回合。当前记录的流程包括启动、开始配送、自动保存、恢复、进入战斗、战斗胜利、完成配送、读取或写入失败和正常退出。

诊断只写入本机，不联网、不上传，也不包含用户名、设备标识、输入内容或其他个人信息。删除 `Diagnostics` 文件夹即可清除全部诊断。

## 构建前验证

`Tools > Sky Courier > Validate Core Rules` 会验证：

- v2 存档 JSON 往返；
- 主存档损坏后的备份恢复；
- v1 存档迁移到 v2 和历史种子；
- 遭遇种子派生稳定且包含航点身份；
- 相同种子生成相同编队、初始手牌和敌人状态；
- JSONL 诊断记录可写入并读回。

## 面向试玩反馈的最小信息

玩家报告问题时，只需提供：

1. 结算、暂停或航线界面显示的 `RUN SEED`；
2. 问题发生在哪个航点或战斗；
3. 如愿意，附上 `latest-run.jsonl` 和 `last-error.json`。

即使玩家不提供诊断文件，种子和航点也足以复现遭遇入口。
